# quobyte-test Standup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a throwaway, cost-minimized GCP sandbox running Quobyte Free Edition on raw-VM k3s, prove CSI dynamic RWX provisioning, evaluate the S3 gateway, execute failure drills, and record empirical findings.

**Architecture:** OpenTofu provisions 1 `e2-medium` control-plane + 3 `e2-standard-2` workers on raw GCP VMs. k3s is bootstrapped with version pinned to `v1.34` and Quobyte network sysctls applied. Cilium provides pod overlay networking (`routingMode: tunnel`) and Gateway API routing. Out-of-tree GCE PD CSI provides dynamic volume provisioning for Quobyte data/metadata devices (all `pd-standard`, 0 SSD quota). Quobyte Free Edition cluster, client, and CSI driver are deployed via Helm.

**Tech Stack:** OpenTofu, Google Cloud Platform (GCE, VPC, IAM), k3s v1.34, Cilium 1.19 (tunnel mode, Hubble, Gateway API), GCE PD CSI driver, Quobyte Helm Charts (quobyte-cluster, quobyte-client, quobyte-csi), Python 3, Just.

## Global Constraints

- k3s release channel pinned to `v1.34` (`quobyte-cluster` caps at 1.35).
- All boot and storage disks must be `pd-standard` (zero `pd-ssd` or `pd-balanced` to protect 250 GB `SSD_TOTAL_GB` quota).
- Regional `E2_CPUS` quota limit is 8: 1× `e2-medium` control plane (2 vCPU) + 3× `e2-standard-2` workers (6 vCPU) = 8 vCPUs.
- Admin ports (22, 6443) must be restricted to Google IAP CIDR (`35.235.240.0/20`).
- Quobyte node sysctls: `net.core.rmem_max = 67108864`, `net.core.wmem_max = 1048576`.
- Client and CSI charts must override namespace endpoints to `quobyte.quobyte.svc.cluster.local`.
- Unlicensed cluster behavior must be observed and documented prior to any license key import.
